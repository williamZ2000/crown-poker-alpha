## #D01 — 2026-07-02: 项目管理机制确立

**背景**: 新项目 crown&poker-alpha 启动，需要一套多 AI 平台（WorkBuddy + Trae）协作的项目管理机制。

**决策**: 采用 5 机制 + 15 文件的轻量管理方案，核心原则：
- 决策权归张总，AI 只做建议和执行
- WorkBuddy = 项目经理/产品经理（只改文档）+ 代码审核验收
- Trae = 技术开发（只改代码/Unity，操作 MCP）
- Git 作为唯一事实源
- 设计文档 → 开发文档 → 代码实现，严格单向依赖

**影响**: 
- 创建了 16 个基础设施文件
- 确立了审批五步闭环、决策联动更新、状态同步等工作流
- Trae 规则已配置（.trae/rules/ai-project-rules.md，Always Apply）

## #D02 — 2026-07-03: 游戏设计架构升级

**背景**: 旧版 Godot v1 为简单"出牌打伤害"玩法，新版目标为卡牌构筑 + 自走棋战斗的成长构筑流。

**决策**:
1. **点数 → 兵种线**：小点数（2-5）前排肉盾，中点数（6-9）均衡，大点数（10-A）后排远程
2. **牌型 → 特殊兵种**：顺子=骑兵、同花=精英兵种、炸弹=超模单位、同花顺=终极单位
3. **花色不直接对应职业**，避免随机性过强；仅用于牌型判定（同花）和派系叙事
4. **构筑系统双线分离**：
   - 战斗单位线：阵营兵种池（基础/精英/传奇）+ 牌型召唤 + 英雄特殊单位 + 商店道具
   - 卡牌线：商店买牌/删牌/升级 + 卡牌效率道具
5. **派系阵营系统**：开局选派系决定兵种池，派系×英雄产生"海克斯"式阵营天赋引导
6. **英雄特殊兵种奖励**：将领、召唤物、魔兽等超模单位

**影响**:
- `docs/design/design.md` 全文重写（12 个章节）
- 后续需讨论：阵营 IP 具体设定、英雄角色、数值细节
- 技术架构文档（§M0-04）需等设计定稿后再开始

**关联文件**: docs/design/design.md, docs/archive/design-v1-godot.md

## #D03 — 2026-07-02/03: Unity MCP 环境搭建

**背景**: M0-02 需要在 Trae + Unity 之间建立 MCP 连接。

**决策**:
- Unity 项目使用 **Universal 2D (URP)** 模板（而非 Built-in 2D）
- Unity 项目放在工作区子目录 `C&P-game-alpha/`，方便 Trae 直接操作 C# 脚本
- MCP 包使用 **CoplayDev/unity-mcp**（与 test10086 同款）
- Git URL 拉取失败时，从 test10086 本地缓存离线安装（`Add package from disk`）
- MCP 服务器监听 localhost:8080，Trae 通过 `{"mcpServers": {"unityMCP": {"url": "http://localhost:8080/mcp"}}}` 连接

**影响**:
- Unity 2D URP 项目已创建并验证通过
- 三端联通（Unity ↔ Python server ↔ Trae）

## #D04 — 2026-07-13: 回合系统大改 + P0 闭环

**背景**: 设计审计发现核心操作闭环缺失大量细节，张总提出自由化方向。

**决策**:
1. 手牌上限 13 张，起手 13 张，自动补满
2. 多轮出牌（基础 3 轮，道具可扩），单轮无上限，随时可"开战"
3. 灵活牌型：飞机、连对、超 4 张炸弹、超 5 张同花顺等
4. 高效低效奖惩：高效(轮次少+余牌少)→金币，低效→敌方增强
5. 站位手动可调
6. 战斗双时限：180s 绝对 + 10s 静默结束
7. 关卡无上限，每关 3 回合(末回合 Boss)，指数难度，关 4&8 陡增
8. 伤害公式 ATK-DEF，棋子属性集 6 个

**影响**: docs/design/design.md §2、§3、§7、§10 大幅重写

## #D05 — 2026-07-23: Buff 被动叠加系统取代羁绊

**背景**: 张总明确不要传统自走棋"同阵营羁绊"，要小丑牌式 Buff 自由叠加。

**决策**:
1. 双载体：将领兵种（上场+全局 Buff，占将领槽）+ 装备（占装备槽）
2. 英雄自身被动 1 个，不占槽
3. 槽位独立计算、可成长，数量待定
4. Buff 作用于四阶段：抽牌/出牌/战斗/结算，结算阶段克制
5. 商店商品类型调整为：装备 / 将领 / 特殊单位 三线

**影响**: docs/design/design.md 新增 §4.4，§6.2、§8.2 联动更新

**关联文件**: docs/design/design.md

## #D06 — 2026-07-24: 棋子留存与升级体系 + BS 模式切换

**背景**: 张总确认倾向自走棋"养军队"模式；棋子跨回合留存；棋盘不设固定格子；文档需要开放多方案讨论。

**决策**:
1. 棋子跨回合留存，阵亡默认永久消失
2. 5% 基础概率受伤存活（50% HP），可被 Buff 提升
3. 棋盘改为 RTS 式自由部署，无固定格子，设单位部署上限（可 Buff 增幅）
4. 满员时多余棋子进入支援区，波次增援补位
5. 棋子升级：3 合 1 升星 + 商店进化券并存，最高 ★★★
6. 失败处理：存活棋子保留，阵亡消失
7. 文档全域切换 Brain Storm 模式，允许保留多方案，正式版再收敛

**影响**: docs/design/design.md 新增 §3.4、§7 重写、§2.1.2 更新、文档状态标记改为 BS

**关联文件**: docs/design/design.md

## #D07 — 2026-07-27/28: BS 阶段全面补完

**背景**: 全文档审计发现 5 个完全空白区 + 5 个缺血缺肉区 + 2 个逻辑矛盾，逐项讨论定稿。

**决策**:
1. **双线互动**：金币唯一资源，玩家自主分配。裁剪三个方向
2. **特殊属性牌**：六类属性参照小丑牌塔罗牌
3. **经济系统**：利息每10金1利/上限5，7项来源(无连胜连败)，商店跳过不惩罚利息
4. **英雄系统**：英雄上战场参战，主动+被动技能，4槽位等级解锁
5. **局外成长**：解锁阵营/英雄/将领 + 难度分层(数值+玩法限制)
6. **敌人AI**：脚本模板+随机变量，三回合递增结构
7. **缺陷修复**：失败→败一次即终局；高效低效→贪婪存钱 vs 稳健部署
