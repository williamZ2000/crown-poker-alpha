## #D01 — 2026-07-02: 项目管理机制确立

**背景**: 新项目 crown&poker-alpha 启动，需要一套多 AI 平台（WorkBuddy + Trae）协作的项目管理机制。

**决策**: 采用 5 机制 + 15 文件的轻量管理方案，核心原则：
- 决策权归张总，AI 只做建议和执行
- WorkBuddy = 项目经理/产品经理（只改文档）+ 代码审核验收
- Trae = 技术开发（只改代码/Unity，操作 MCP）
- Git 作为唯一事实源
- 设计文档 → 开发文档 → 代码实现，严格单向依赖

**影响**: 
- 创建了 16 个基础设施文件
- 确立了审批五步闭环、决策联动更新、状态同步等工作流
- Trae 规则已配置（.trae/rules/ai-project-rules.md，Always Apply）

## #D02 — 2026-07-03: 游戏设计架构升级

**背景**: 旧版 Godot v1 为简单"出牌打伤害"玩法，新版目标为卡牌构筑 + 自走棋战斗的成长构筑流。

**决策**:
1. **点数 → 兵种线**：小点数（2-5）前排肉盾，中点数（6-9）均衡，大点数（10-A）后排远程
2. **牌型 → 特殊兵种**：顺子=骑兵、同花=精英兵种、炸弹=超模单位、同花顺=终极单位
3. **花色不直接对应职业**，避免随机性过强；仅用于牌型判定（同花）和派系叙事
4. **构筑系统双线分离**：
   - 战斗单位线：阵营兵种池（基础/精英/传奇）+ 牌型召唤 + 英雄特殊单位 + 商店道具
   - 卡牌线：商店买牌/删牌/升级 + 卡牌效率道具
5. **派系阵营系统**：开局选派系决定兵种池，派系×英雄产生"海克斯"式阵营天赋引导
6. **英雄特殊兵种奖励**：将领、召唤物、魔兽等超模单位

**影响**:
- `docs/design/design.md` 全文重写（12 个章节）
- 后续需讨论：阵营 IP 具体设定、英雄角色、数值细节
- 技术架构文档（§M0-04）需等设计定稿后再开始

**关联文件**: docs/design/design.md, docs/archive/design-v1-godot.md

## #D03 — 2026-07-02/03: Unity MCP 环境搭建

**背景**: M0-02 需要在 Trae + Unity 之间建立 MCP 连接。

**决策**:
- Unity 项目使用 **Universal 2D (URP)** 模板（而非 Built-in 2D）
- Unity 项目放在工作区子目录 `C&P-game-alpha/`，方便 Trae 直接操作 C# 脚本
- MCP 包使用 **CoplayDev/unity-mcp**（与 test10086 同款）
- Git URL 拉取失败时，从 test10086 本地缓存离线安装（`Add package from disk`）
- MCP 服务器监听 localhost:8080，Trae 通过 `{"mcpServers": {"unityMCP": {"url": "http://localhost:8080/mcp"}}}` 连接

**影响**:
- Unity 2D URP 项目已创建并验证通过
- 三端联通（Unity ↔ Python server ↔ Trae）
